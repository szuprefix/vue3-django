# 敏捷迭代计划

## 原则

每轮完成一个能演示、能验收的业务闭环。复用旧版模型标识、元数据、配置和事件语义；Vue 2 专属生命周期和组件写法在迁移页面时改为 Vue 3。保留 JavaScript 与 Options API 的选择，不强制业务全面改写为 TypeScript 或 Composition API。

## 第 1 轮：模型 CRUD 基础（本次实现）

- 从真实旧源码确认 apps.models 注册、app.model、OPTIONS actions、config.js、尾斜杠、Token/CSRF、code/msg 错误和 form-posted 约定。
- 提供独立 HTTP/Registry/AppModel；注册表按实例隔离，元数据并发去重并缓存，失败可重试。
- 元数据字段 + 配置覆盖的列表、搜索、页码分页、新增、编辑、函数/API 行动作。
- 同一模型层驱动 Element Plus 与 Vant，支持字段插槽和自定义组件。
- 本地演示、模型协议和两端组件测试、库构建及演示构建。

验收：演示两端读取同一批项目；搜索与翻页；新增、修改及暂停；重复名称显示字段错误；false/0 不丢失；部署前缀保留；保存不包含只读字段。

## 第 2 轮：真实业务试迁移

选一个低风险、包含外键与权限的业务模型，记录真实 OPTIONS、查询、400 和权限响应（脱敏）。实现登录态、401/403 处理与刷新后的身份恢复；读取原 user.model_permissions 并控制可用动作；后端权限作为实际校验。对齐菜单/路由并保留旧页面入口以便回退。明确主键、复杂字段、过滤器和权限的真实契约，再扩展基础层。

完成条件：同一后端下新旧页面的查询和保存结果一致；完整走通登录、无权访问、错误修复与回退。

## 第 3 轮：关系与动作

外键搜索/显示、多对多、父子查询、generic_foreign_key、SEARCH filter_fields、排序、批量选择及 batchActions（ids + context）。建立 scoped 事件机制替代 Vue 2 bus，用 posted/deleted 刷新依赖模型，明确失败、取消和确认行为。

## 第 4 轮：高频扩展

分组表单、嵌套字段、JSON、文件上传、导入导出、异步任务进度。按首个真实业务的使用频率排序，每轮只实现被验证需要的能力。

## 第 5 轮：逐步推广

第二个独立业务接入，验证配置与插件扩展边界、按端入口及依赖拆分、包声明和发布流程。建立变更日志和版本兼容策略，再扩大替换范围。

## 首轮明确缺口

未接实际 DRF 服务；没有身份/权限界面、Vue Router/Vuex 替代、自动菜单、复杂搜索、外键选择、批量动作、删除界面、上传、导入导出和旧事件总线。当前不会解析字符串路由动作；需要宿主提供 do 函数。移动 choices 使用原生 select，日期输入尚未接 Vant Picker。嵌套验证错误暂以 JSON 显示。首轮未发布 npm、未改动旧仓库。
